# Semark CRM — повний вихідний код

CRM для ТОВ «Семарк»: клієнти, контакти компаній, задачі, продажі, сервіс, оренда, обладнання, історія подій, користувачі та ролі.

## Склад архіву

| Папка / файл | Що це |
|---|---|
| `client/` | Інтерфейс (React + TypeScript + Tailwind) |
| `server/` | Серверна частина (Node.js + Express): API, вхід, перевірка прав |
| `server/auth.ts` | Вхід по email/паролю, токени (JWT, HMAC-SHA256), захист API |
| `server/routes.ts` | Усі API-маршрути |
| `server/storage.ts` | Робота з базою: таблиці, запити, історія подій |
| `shared/schema.ts` | Структура таблиць бази |
| `shared/access.ts` | Ролі та хто має право на імпорт/експорт |
| `data.db` | База даних SQLite з усіма поточними даними |
| `Dockerfile`, `docker-compose.yml` | Запуск на сервері через Docker |
| `.env.example` | Приклад налаштувань |

## База даних

Файл `data.db` (SQLite). Таблиці: `users`, `leads` (клієнти), `contacts`, `tasks`, `sales`, `repairs` (сервіс), `rentals`, `equipment`, `events` (історія).

Паролі зберігаються тільки як хеш (scrypt), у відкритому вигляді їх немає.

Резервна копія = копія файлу `data.db` (робіть її, коли CRM зупинена).

Переглянути базу можна безкоштовною програмою DB Browser for SQLite.

## Запуск на сервері через Docker (рекомендовано)

1. Скопіюйте папку на сервер (Linux, VPS).
2. Створіть файл налаштувань:
   ```
   cp .env.example .env
   ```
   В `.env` замініть `AUTH_SECRET` на свій довгий випадковий рядок.
3. Запустіть:
   ```
   docker compose up -d --build
   ```
4. Відкрийте `http://IP-сервера:5000`.

Для домену з https поставте перед CRM Nginx або Caddy, щоб він передавав запити на порт 5000.

## Запуск без Docker (Linux / macOS / WSL)

Потрібен Node.js 20.

```
npm install
npm run build
PORT=5000 AUTH_SECRET=ваш-секрет npm start
```

Режим розробки: `npm run dev`.

На Windows найпростіше запускати через Docker Desktop або WSL. Команди `npm run dev/start` написані у форматі Linux.

## Резервні копії

`npm run backup` робить цілісну копію бази просто під час роботи CRM і перевіряє її. Копії лягають у `BACKUP_DIR` (типово `backups/`), старші за `BACKUP_KEEP_DAYS` днів (типово 30) видаляються. Запускати щоночі через планувальник задач (cron) хостингу. Відновлення: зупинити CRM, підставити файл копії замість бази (`DB_PATH`), запустити.

## Вхід

Облікові записи і паролі в цьому файлі не зберігаються.

- У робочому режимі (`npm start`, Docker) нова база порожня: демо-користувачі й демо-дані створюються лише в режимі розробки (`npm run dev`).
- Першого адміністратора задають у `.env`: `ADMIN_EMAIL`, `ADMIN_PASSWORD` (щонайменше 10 символів), за бажанням `ADMIN_NAME`. Якщо користувач з таким email уже є, сервер лише змінить йому пароль — так само відновлюють доступ. Після входу приберіть `ADMIN_PASSWORD` з `.env` і перезапустіть CRM.
- Паролі коротші за 10 символів у робочому режимі не приймаються, тому користувачі зі старими демо-паролями зможуть увійти лише після того, як директор задасть їм новий пароль у «Налаштуваннях».
- Після 5 невдалих спроб входу для пари IP + email вхід блокується на 15 хвилин.
- Без надійного `AUTH_SECRET` (щонайменше 32 символи) сервер у робочому режимі не запуститься.

## Важливо

- Без `AUTH_SECRET` сервер створює новий секрет при кожному запуску, і всі користувачі виходять із системи після перезапуску.
- Сесія живе в пам'яті сторінки: після оновлення сторінки треба увійти знову.
- Імпорт і експорт дозволені ролям «Директор» і «Виконавчий директор» (`shared/access.ts`).
- Windows-застосунок відкриває онлайн-адресу CRM. Якщо перенесете CRM на свій сервер, застосунок треба перезібрати з новою адресою.
